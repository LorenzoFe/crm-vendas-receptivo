- Publicação via **Blueprint do Render** (`render.yaml`), que cria juntos:
  - **crm-vendas-db:** PostgreSQL gerenciado (plano free), banco `crm_vendas`
  - **crm-vendas-api:** API em Docker, ligada ao banco pelas variáveis `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USERNAME` e `DB_PASSWORD`
- Na primeira subida a aplicação executa `schema.sql` e `dados_iniciais.sql` (os scripts do CP-1) e cria o usuário admin; a senha do admin é gerada pelo Render e fica só nas variáveis de ambiente.
- `JWT_SECRET` e senhas ficam apenas no painel do Render, nunca no repositório.
- Health check apontando para `/v3/api-docs`.
- CORS configurável por `CORS_ALLOWED_ORIGINS`, para liberar o endereço do frontend quando ele for publicado.
- O frontend será publicado no Render como site estático, com `.env.production` apontando para a URL da API.
- PR #6 (configuração de deploy no Render com CORS, banco automático e admin inicial) mergeado; API no ar e Swagger acessível em produção.
